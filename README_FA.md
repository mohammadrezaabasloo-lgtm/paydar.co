# بستهٔ پروژهٔ PM تجهیزات (نسخهٔ اولیهٔ MAUI)

این بسته، فایل HTML موجود را در یک WebView محلی قرار می‌دهد تا اسکلت برنامهٔ قابل ساخت برای Windows و Android فراهم شود.

## پیش‌نیازها
- Windows 10/11
- .NET 8 SDK
- Visual Studio 2022 با workload مربوط به .NET MAUI
- برای Android: Android SDK و ابزارهای لازم که از Visual Studio نصب می‌شوند.

## باز کردن پروژه
فایل `PMEquipment.csproj` را در Visual Studio باز کنید و workloadهای لازم را نصب/Restore کنید.

## ساخت برای Windows
در ترمینال Developer یا پوشهٔ پروژه:
```powershell
dotnet workload install maui
dotnet restore
dotnet publish -f net8.0-windows10.0.19041.0 -c Release -p:WindowsPackageType=None
```

## ساخت برای Android
پس از نصب Android SDK:
```powershell
dotnet publish -f net8.0-android -c Release
```
برای تولید APK قابل نصب ممکن است لازم باشد تنظیمات امضای Release را نیز در محیط ساخت تکمیل کنید.

## نکات مهم پیش از بهره‌برداری
1. این بسته «پروژهٔ قابل ساخت» است، نه فایل EXE یا APK ساخته و آزمایش‌شده.
2. فایل HTML در `Resources/Raw/index.html` قرار گرفته و در اولین اجرا به پوشهٔ دادهٔ برنامه کپی می‌شود.
3. داده‌های `localStorage` در فضای WebView همان نصب برنامه نگهداری می‌شوند. حذف برنامه/پاک‌کردن داده‌های آن می‌تواند داده‌ها را از بین ببرد؛ از خروجی JSON/Excel برای پشتیبان‌گیری استفاده کنید.
4. کتابخانهٔ SheetJS اکنون به‌صورت فایل محلی `Resources/Raw/xlsx.full.min.js` داخل پروژه بسته‌بندی شده است. برنامه در اولین اجرا آن را کنار `index.html` در پوشهٔ دادهٔ محلی کپی می‌کند؛ بنابراین ورود/خروج اکسل به دریافت کتابخانه از اینترنت وابسته نیست.
5. قابلیت ارسال پیامک و هر اتصال API خارجی به اینترنت و تنظیمات معتبر سرویس‌دهنده وابسته است. کلید API را در نسخهٔ عمومی برنامه قرار ندهید.
6. این نسخه هنوز روی دستگاه Windows یا Android اجرا و آزمون نشده است. پیش از استفادهٔ عملی، ورود/خروج اطلاعات، گزارش‌ها، اکسل، ذخیره‌سازی و مسیرهای فایل در هر دو پلتفرم آزمایش شوند.
7. شناسهٔ برنامه (`ApplicationId`) نمونه است؛ پیش از انتشار باید به شناسهٔ یکتای متعلق به شما تغییر کند.


## تغییرات این بسته
- فایل `xlsx.full.min.js` به `Resources/Raw` اضافه شده است.
- ارجاع CDN در `index.html` با ارجاع محلی `xlsx.full.min.js` جایگزین شده است.
- در `MainPage.xaml.cs` هر دو فایل `index.html` و `xlsx.full.min.js` در اولین اجرا به `FileSystem.AppDataDirectory` کپی می‌شوند.
- فایل‌های کپی‌شده در پوشهٔ محلی کنار هم قرار می‌گیرند تا مرورگر داخلی بتواند کتابخانه را با مسیر نسبی بارگذاری کند.

## نکتهٔ به‌روزرسانی
اگر نسخهٔ قبلی برنامه را قبلاً اجرا کرده‌اید و `index.html` قدیمی در پوشهٔ دادهٔ برنامه باقی مانده است، برای اطمینان از دریافت فایل‌های جدید، داده‌های برنامه را پاک کنید یا برنامه را حذف و دوباره نصب کنید. این کار ممکن است اطلاعات ذخیره‌شدهٔ محلی را پاک کند؛ پیش از آن از اطلاعات نسخهٔ قبلی خروجی پشتیبان بگیرید.

## ساخت فایل اجرایی ویندوز بدون نصب ابزار توسعه روی رایانهٔ شما

در این نسخه، فایل گردش‌کار GitHub Actions اضافه شده است تا ساخت برنامه روی یک رایانهٔ مجازی ویندوزی انجام شود.

1. در سایت GitHub یک حساب کاربری بسازید یا وارد حساب خود شوید.
2. یک مخزن (Repository) جدید و ترجیحاً Private ایجاد کنید.
3. محتوای این پوشه را در مخزن بارگذاری کنید؛ فایل `PMEquipment.csproj` باید در ریشهٔ مخزن باشد.
4. وارد زبانهٔ **Actions** شوید و در صورت درخواست، فعال‌سازی GitHub Actions را تأیید کنید.
5. گردش‌کار **Build Windows EXE** را از فهرست سمت چپ انتخاب کنید و روی **Run workflow** بزنید. اگر فایل‌ها را در شاخهٔ `main` یا `master` بارگذاری کرده باشید، ساخت با Push نیز خودکار آغاز می‌شود.
6. پس از پایان موفق، وارد همان اجرای گردش‌کار شوید و از بخش **Artifacts** فایل `PMEquipment-Windows-EXE` را دریافت کنید.
7. فایل ZIP دریافت‌شده را در ویندوز Extract کنید و فایل `PMEquipment.exe` را اجرا کنید.

**توجه:** این روش ساخت را روی زیرساخت ویندوز GitHub انجام می‌دهد؛ در این مرحله هنوز فایل EXE ساخته یا روی ویندوز آزمایش نشده است. اگر ساخت با خطا متوقف شد، متن کامل خطای مرحلهٔ قرمز را ارسال کنید تا پروژه اصلاح شود. این نسخه نیز هنوز از نظر عملکرد کامل برنامه، ورود/خروج Excel و ذخیره‌سازی تأیید نهایی نشده است.
